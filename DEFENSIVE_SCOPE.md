# Defensive scope and model boundaries

This tool assists review of caller-owned DNS configurations. A strict manifest names every file and asserts one zone origin per snapshot. Parsing uses source bytes rather than regular-expression extraction. Labels preserve escaped octets; unescaped dots separate labels, and only ASCII uppercase octets are folded. Owners omitted through leading whitespace retain the previous absolute owner even after `$ORIGIN` changes. TTL and IN class may appear in either order. RDATA is normalized by type; TXT contents remain octets. The profile requires explicit/default TTLs and rejects unsupported syntax with a position.

The graph separates parent NS cuts and glue from the child's records. Required glue applies to nameserver names at or below that delegation's origin. Sibling/out-of-domain nameserver names do not automatically require that in-domain glue. Their address resolution, reachability, cyclic sibling dependencies, DNS packet size and TC behavior are outside the model and covered by the permanent live-DNS OPEN boundary. Parent and child apex NS sets are compared as a selected consistency policy. Parent data below a cut other than addresses of its named NS targets fails the selected configuration policy; it is never used as an authoritative answer.

Each NS record at an apex, parent delegation or child apex is reviewed for a direct CNAME at its target, as prohibited by [RFC 2181 section 10.3](https://www.rfc-editor.org/rfc/rfc2181.html#section-10.3). The source zone and target authority must be reachable from the entry zone through supplied, complete, resolved cuts. The target CNAME witness includes its record digest and numerical source position. Parent records below a cut, including glue or a wrongly cached CNAME, cannot establish the child's target alias property. Missing/incomplete target authority, targets outside the entry origin, orphan source snapshots and strict descendants hidden by DNAME yield OPEN. An exact DNAME owner is not automatically an alias. This check does not prove required target addresses, recursive nameserver reachability, DNAME-generated NS aliases, or the corresponding MX restriction.

Every original query and rewritten alias restarts at `entry_zone`; traversal enters only a supplied child matching a parent cut. An unrelated loaded child does not bypass that cut. Missing/incomplete child data, invalid visited zones, targets outside the entry origin, wildcards, unsupported records or budgets produce OPEN. A supplied but unvisited incomplete zone can leave a particular finite query decided while the overall review stays OPEN. A CNAME-record query may establish record presence even if its external target causes an overall OPEN.

DNAME applies only to strict descendants and rewrites a whole-label suffix. The owner itself can contain other selected records. Descendant records in the same zone are flagged as occluded. Multiple targets and targets at or below the DNAME owner fail selected structural checks. A CNAME query below DNAME can terminate with a synthesized CNAME. DNS name-size overflow is YXDOMAIN plus a configuration FAIL. Root DNAME is OPEN. Repeated exact `(zone, name, type)` states establish a supplied-query loop; budget exhaustion is OPEN rather than proof of a loop. Explicit CNAME cycles are separately checked within authoritative data of each asserted zone. No universal DNAME termination claim is made.

Unsupported directives stop the zone parser; earlier records remain available for positive structural violations, but that zone cannot yield a query PASS. Missing files never manufacture negative apex findings. Unsupported RR classes/types, DNSSEC exceptions, wildcards, unknown query properties and malformed manifests remain OPEN. This is a selected static profile, not full BIND compatibility or GRoot behavioral equivalence.

No equivalence-class construction, wildcard/closest-encloser response semantics, multiple authoritative-server variants, all possible queries, recursive server-address lookup, DNSSEC validation, resolver caching, protocol replies or online measurements are implemented. `RESOLVES`/`NOT_RESOLVES` refer to requested-type record presence in this finite model, not connectivity or actual DNS service. CVP acceptance and deployed security remain OPEN regardless of local PASS.

Files are opened through a held authorized-root descriptor after every root component is checked without following symlinks. Relative file paths are similarly traversed with O_NOFOLLOW directory descriptors. Read identity and length are checked, but the tool does not claim transactional consistency across different files: the caller must supply a coherent snapshot. Special files, external includes, URL/stdin/archive input, code execution, automatic remediation and write-back are excluded.

Findings use fixed codes and numerical locations; query paths identify normalized names and witness records by hash. These hashes permit correlation without literal disclosure, but can reveal guessable names through a dictionary attack. Work, input, graph, trace and report sizes are bounded. When an aggregate work budget stops the review, remaining properties are unassessed and completeness becomes OPEN. Report compaction retains known violation counts.
